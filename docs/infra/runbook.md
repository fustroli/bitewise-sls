# Serverless runbook (console first, then CDK)

Manual setup of the serverless stack from `docs/plan.md`, built next to the EC2 app.
Everything is created by hand in the console. After each section, the **CDK** step writes the
same resources as CDK code in `infra/` and checks it with `cdk synth` (renders the CloudFormation
template, deploys nothing). That code is documentation for a later rebuild: only `cdk deploy` it
after tearing down the hand-made resources (`cleanup.md`), or names will clash.
Region: `us-east-1`. Fill in the values you chose. Tag every resource `app=bitewise-sls`.
Whenever a step creates something, add its delete step to `cleanup.md`.

## Gotchas hit

- CDK: `httpApi.addStage()` with `stageName: '$default'` renders the API resource twice ("section 'Resources'
  already contains …" at synth). A standalone `new HttpStage(...)` works.
- The route's "Choose an existing integration" dropdown lists integrations (API → function links), not
  functions: a new Lambda needs "Create and attach an integration" once, then the second route reuses it.
  Creating it twice leaves a duplicate integration (happened for ingredients).
- A 401 from the HTTP API explains itself in the `www-authenticate` header (`curl -i`). "token contains an
  invalid number of segments" meant the shell's `AUTH` variable still held `Bearer null` from a failed
  code exchange; rebuild `AUTH` after every new `TOKEN`.
- Lambda console asks "Event function" or "Web function": triggers are Event functions (no URL).
- Managed login is email-first: "Forgot your password?" only shows after Next, on the password step.
- Google → native linking in pre-sign-up worked on the first sign-in; the reported "Already found an
  entry for username" first-attempt error did not occur.
- CloudFront's Free flat-rate plan offers only managed response headers policies ("Custom: available
  with the Business plan"), so no custom CSP header. The CSP is a per-page `<meta>` tag instead: a
  static export has no nonce, so `web/scripts/csp.ts` hashes each page's inline scripts (theme,
  Turbopack bootstrap, RSC payload; they change with the code) at build time. A meta CSP can't carry
  `frame-ancestors`; the managed policy's X-Frame-Options SAMEORIGIN covers framing.
- HTTP API CORS doesn't help the SPA: preflight `OPTIONS` matches the `ANY` routes and gets the JWT
  authorizer's 401 (an `OPTIONS /{proxy+}` route loses to the exact-path `ANY` routes). `next dev`
  proxies `/api/*` to the app domain instead (dev-only rewrite), so the API needs no CORS.
- Web app Google sign-in: `redirect_mismatch`, then one failed sign-in right after fixing the app
  client's callback URLs; the next try worked (settings take a moment). The app logs the cause as
  `Google sign-in failed` in the browser console.
- Cognito quick setup: sign-in identifiers and required attributes can't be changed after
  creation; a wrong choice means recreating the pool.
- Cognito SES settings: the FROM field is a dropdown of verified SES identities (pick the domain);
  the actual address goes in "FROM sender name" as `BiteWise <no-reply@rolandfuest.com>`.
- CDK `TableV2` synthesizes `AWS::DynamoDB::GlobalTable` (one replica), not the
  `AWS::DynamoDB::Table` the console creates. Same table to the app; only matters for `cdk import`.

- HTTP API route throttling can't be created in the console ("Use the CLI or an SDK to create custom
  route settings"); the console only edits existing ones. Created once from CloudShell with
  `aws apigatewayv2 update-stage --route-settings`.
- A trailing space pasted into `AVATAR_BUCKET` (both Lambdas): S3 `InvalidBucketName` with
  `"BucketName":"bitewise-sls-avatars-… "`, and the presigned URL turned path-style ending in `%20`. The
  processor's memory edit (1024 MB) also hadn't saved: `REPORT` lines show `Memory Size`, check them.
- A deleted avatar stays reachable from CloudFront's edge cache (`CachingOptimized`, up to a year; the
  query string isn't in the cache key, so `?v=` doesn't bypass it). Its URL is never referenced again.
